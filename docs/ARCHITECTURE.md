# 架构与扩展边界

```
Godot 4.4.1 / Forward+
  scripts/main.gd       中文界面、质量输入、固定回调调度、场景更新
  scripts/camera.gd     旋转、缩放、自由平移
  shaders/             地表、云层、大气、程序化星空
          │ GDExtension API；SI 数据为 PackedFloat64Array
  SolarSimulation      固定步长累积器、预算、诊断、数值轨道预览
          │ 不把 Godot Vector3 传入积分器
  solar::System        通用 N 体、双向引力、Velocity Verlet、接触保护
  solar::Body          唯一 ID、质量、物理半径、自转周期、双精度位置/速度
```

## 数值与显示

- 物理单位为 kg、m、s，G = 6.67430e-11 m³·kg⁻¹·s⁻²。无软化项，无固定公转轨迹。
- 每对天体的同一个引力场向量分别乘对方质量，避免独立循环产生不对称力。
- Velocity Verlet：计算旧加速度、半步速度／漂移、计算新加速度、完成速度更新。循环使用预分配数组，不在每个积分步分配天体内存。
- 渲染用 1 单位 = 1000 km。`get_render_positions` 在 C++ double 中先减观察天体坐标，再缩放为 Godot 单精度 Vector3；物理状态不随相机移动。真实比例和视觉放大仅影响 MeshInstance 的 scale。
- 正常场景通过 Godot `_physics_process` 调度固定物理步、`_process` 更新绘制。动力学步长不等于渲染帧间隔。×1 下 60 秒固定步长会产生每 60 秒一次的位置更新；追求低倍率平滑可选 10 秒步长，本阶段尚未做渲染插值。
- 高倍率达到 3ms 软预算或每回调 4096 步上限时限制实际推进，不扩大 dt，不积攒无限追赶任务。窗口卡顿最多记入 0.25 秒调度时间；UI 测量实际倍率。
- 轨道预览复制物理系统，用同一求解器以最多 600 秒步长预测 30 天；不修改真实状态，不驱动天体。质量输入防抖后更新。实际轨迹最多保留 2048 个采样点。
- 场景初始为惯性系质心静止的地月系统。编辑质量保留惯性状态，因此新质心可以移动；这不是数值漂移。编辑即重新记录守恒误差基线。
- C++ 诊断能量不包含自转内能或引力形变能；报告的是点质量平动动能与成对引力势能，角动量为公转角动量。

## 目录

- `native/core/`：独立可测试的 C++17 核心；不依赖 Godot。
- `native/extension/`：Godot 绑定与时间调度。
- `native/tests/`：真正执行的稳定性、守恒、解析 Kepler 收敛、N 体和质量修改测试。
- `godot/`：可打开的 Godot 项目；`bin/solar_physics.gdextension` 必须保留。
- `tools/`：Windows／Linux 构建、依赖验证、资源哈希验证。
- `third_party/godot-cpp/`：固定版本绑定源码。
- `docs/`：数据来源、测试记录、许可证、操作说明。

## 第二阶段如何进入

当前只交付阶段一。下一阶段从 `System::set_bodies()` 现有通用 N 体接口进入：

1. 新增有来源、单位、历元和参考系的太阳系数据文件；若使用 Horizons，记录太阳系质心参考系和 J2000／历元，而不是混用日心和地心状态。
2. 先在 C++ 加入太阳与八大行星，扩展多体守恒测试；再建立以天体 ID 索引的渲染节点注册表，替换界面中“只处理两个球体”的逻辑。
3. 加入质量／速度／位置的事务式编辑，验证极端参数和接触保护。预览线程应从不可变快照计算，主线程只交换完成的结果。
4. 加入主要卫星、NASA 等真实纹理、土星环；仍维持物理半径与渲染半径分离。
5. 小行星带明确分为低成本 Kepler 背景实例与有质量高精度实体；使用 MultiMesh，选中时以连续状态提升为真正物理实体。背景近似必须在界面标明。

第三阶段才引入碰撞响应、质量与动量守恒的碎片生成以及每块碎片独立状态。第四阶段再用经过误差验证的 Barnes–Hut、空间宽相和工作线程扩展 1000–2000 片。不能从本阶段的两体测试推出碎片性能保证。
